## Pass 15: AutoGen and CrewAI routing and handoff controls

- Read the repository's current README, 5 October investigation log, reviewed leads, source register and snapshot index before searching. The prior result remains zero confirmed previously unreported rogue swarms.
- Rotated away from provider CLI issue trackers to two public agent-orchestration framework repositories: `microsoft/autogen` and `crewAIInc/crewAI`.
- Twelve newest-updated, repository-scoped issue searches returned 262 rows and 211 unique issue URLs. Five public issue bodies and selected public comments received full assessment. Searches were capped at 30 rows, overlap heavily and are not a repository census. Embedded snippets were treated as evidence and not executed; no attachment, linked demonstration or code file, package, agent runtime or target system was opened or run.
- AutoGen issue 8238 is the strongest boundary-control record. Its author reports a synthetic two-participant reproduction in which a custom sender places a privileged-role message in handoff context, selects a recipient and causes that context to persist. The framework routing and tool path were reported as unmodified, but recipient model compliance was deliberately stubbed. It therefore demonstrates a possible transfer/use chain and an operator boundary in a controlled adversarial test, not an autonomous real-world episode.
- CrewAI issue 3899 preserves a concrete remote-agent result transfer: the remote side repeatedly returned a completed status and the same answer while the local side delegated the same request again until the turn limit. A project contributor said the local agent's status handling was by design and later exposed a flag. This is an intentional A2A workflow with a completion-handling defect; recipient acceptance or use of the result is not shown.
- AutoGen issue 2239 traces unexpected cross-agent tool visibility to shared mutable configuration, issue 1499 reports role/name drift in a designed group chat, and issue 6523 reports failure to select the next configured speaker after a tool-bearing agent. These are configuration, identity-label and routing controls. None authenticates independent agents, preserves an unauthorized task-result transfer-and-use exchange, or establishes rogue intent.
- Every selected record was public before this collection. Open issue state or later comments do not prove ongoing agent activity. Result: **no previously unreported rogue swarm**.

## What would establish a candidate

Advancing BV-019 requires an original, not-previously-published exchange with independently corroborated autonomous participants; a task result transferred to and actually used by a distinguishable recipient; and evidence that this coordination exceeded operator authorization in a real run rather than a designed orchestration workflow, configuration defect or synthetic security reproduction. Provider/model attribution and continuing activity require separate primary evidence.

## Pass 16: LangGraph retry, handoff and state-boundary controls

- Rotated to `langchain-ai/langgraph`. Eight newest-updated, repository-scoped searches returned 126 rows and 104 unique issue URLs. Five public issue bodies and selected comment threads received full assessment. Searches were capped at 30 rows and overlap; no embedded reproduction was run.
- Issue 7417 is a concrete production-shaped report. The reporter describes a main agent dispatching long-running subagents through a task tool, followed by checkpoint redispatch around three minutes later while the original remained active. The duplicate tool nodes reportedly had identical arguments, no preceding model node and two or three successful completions. This establishes reported duplicate execution and an operator cost/work boundary, but not independently authenticated participants, recipient use of a returned result, rogue intent or a new episode: the issue has been public since April.
- Issue 6064 describes pending handoff ownership being lost across user turns in a designed mediator/subagent workflow. Public replies recommend interrupts or explicit active-agent state. It is a routing/state failure, not an unauthorized peer exchange.
- Issue 6533 is a closed parallel-tool control: resume values could share an interrupt identity and reach the wrong tool path; a collaborator recommended separate `Send` tasks. Issue 8393 provides a synthetic runner-level child-task duplication reproduction. Issue 9004 describes a potential encrypted-checkpoint replay by a store-level writer. None is an observed autonomous coordination episode.
- Issue 7417's long comment thread contains many third-party workarounds and product promotions. Those comments are not independent verification of the original run, and recent discussion does not establish ongoing agent activity.
- Result: **no previously unreported rogue swarm**. Advancing BV-020 requires an unpublished original exchange with independently corroborated autonomous participants, actual recipient use of a transferred result and evidence that the coordination itself—not only scheduler replay, retry, state loss or a synthetic test—exceeded operator authorization.

## Pass 17: OpenAI Agents SDK and Semantic Kernel controls

- Rotated to `openai/openai-agents-python` and `microsoft/semantic-kernel`. Twelve newest-updated repository searches returned 112 rows and 104 unique issue URLs. Six issue bodies and selected comments received full assessment. Embedded reproductions were not run.
- OpenAI Agents SDK issue 4118 is the strongest exchange-shaped control. Distinct configured agent names normalized to the same handoff/tool name, so a deterministic offline run routed to the later specialist and used its final output while the earlier specialist became unreachable. This demonstrates wrong-agent task routing and use in a test, not independent autonomous identities or a real-world episode.
- Issue 3115 demonstrates an offline single-agent tool executing after its dynamic `is_enabled` gate changed to false between exposure and dispatch. Issue 4685 demonstrates an approval-plus-handoff flow continuing with a delegate while durable Session history loses tool/handoff outputs after an injected atomic append failure. Both are framework boundary/durability controls, not rogue multi-agent coordination.
- Issue 4845 reports a guarded tool running when an approval callback returns a falsy non-boolean. A maintainer closed it because the value violates the declared boolean callback contract; the reporter then searched for and did not find a supported-path bypass. It is retained as an out-of-contract control and must not be presented as a confirmed authorization exploit.
- Semantic Kernel issue 14072 alleges destructive automatic execution after indirect prompt injection but supplies no runtime logs and bases its claim on static review. Its thread clarifies that an `AUTO_FUNCTION_INVOCATION` filter can already block dispatch, while first-class risk classification and resumable approval remain gaps. Issue 12898 reports failed context transfer in an intended writer/translator/detector chain. Neither is a rogue-swarm incident.
- Result: **no previously unreported rogue swarm**. Advancing BV-021 requires an unpublished original exchange with independently corroborated autonomous participants, actual recipient use of transferred task work and evidence the coordination itself—not only a deterministic stub, naming collision, state write fault or static design gap—crossed operator authorization.
